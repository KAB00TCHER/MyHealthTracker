# MyHealthTracker — функциональный релиз 1

## Версия 1.0.1
Исправлена навигация: кнопки на главной странице («Заполнить анкету», «Быстрая отметка», «История») теперь открывают соответствующие разделы.

## Что входит
- Telegram initData HMAC verification на сервере.
- Роли user/admin; администратор может только читать записи Леры.
- Ежедневная анкета с сохранением и редактированием записи за дату.
- Внутридневные события отдельно от ежедневной анкеты.
- История анкет и событий.
- Недельный отчёт через печать браузера / сохранение в PDF.
- AES-256-GCM шифрование ответов анкеты и комментариев событий на сервере.

## 1. Загрузить файлы
Распакуйте архив в корень репозитория и замените файлы с совпадающими путями. Не удаляйте `.gitignore`, `index.html` и остальные настройки проекта.

## 2. Выполнить SQL
Откройте Supabase → SQL Editor и выполните `supabase/migration.sql`.
Миграция только добавляет новые nullable-колонки. Старые `answers` и `note` не удаляются.

Важно: записи, которые были сохранены старой версией в plaintext-полях, новая версия не читает. Если такие записи существуют, не удаляйте их; сначала отдельно согласуйте безопасный перенос. Новые записи шифруются до отправки в базу.

## 3. Добавить переменную шифрования в Vercel
Создайте случайный ключ AES-256 (32 байта) в Base64. На компьютере с Node.js выполните:
`node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`

Скопируйте результат в Vercel → Project → Settings → Environment Variables:
`DATA_ENCRYPTION_KEY`

Добавьте для Production (и Preview, если используете). Не присылайте ключ в чат, не добавляйте в GitHub, не храните в исходниках. Сохраните его в надёжном менеджере паролей. Потеря ключа означает невозможность расшифровать данные.

## 4. Остальные переменные Vercel
Должны быть заданы:
- `TELEGRAM_BOT_TOKEN`
- `LERA_TELEGRAM_ID`
- `ADMIN_TELEGRAM_ID`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

`LERA_TELEGRAM_ID` и `ADMIN_TELEGRAM_ID` должны быть разными Telegram ID. Service role key используется только в serverless API и не должен иметь префикс `VITE_`.

## 5. Деплой
После добавления SQL и переменной ключа загрузите файлы в GitHub и выполните обычный Vercel deployment. Без `DATA_ENCRYPTION_KEY` авторизация откроется, но сохранение/чтение зашифрованных данных завершится ошибкой.

## 6. Проверка
1. Откройте Mini App под аккаунтом Леры.
2. Убедитесь, что открывается анкета и можно сохранить тестовую запись.
3. Создайте тестовую быструю отметку.
4. Откройте историю и проверьте, что анкета и события отображаются отдельно.
5. Откройте приложение под администратором: записи видны, кнопок изменения/создания нет.
6. Проверьте в Supabase: `answers_encrypted` и `note_encrypted` содержат envelope с `alg: A256GCM`, а не открытый текст.

## Ограничения релиза
- PDF формируется через окно печати браузера; выберите «Сохранить как PDF».
- Диапазон отчёта — последние 7 календарных дней.
- В этой версии нет удаления записей из интерфейса, восстановления ключа или автоматических резервных копий.
- Старые plaintext-данные не мигрируются автоматически.
